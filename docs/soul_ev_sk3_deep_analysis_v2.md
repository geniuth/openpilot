# Soul EV 조향 engage — 심층 재검증 (테스트 전, 반례/리스크 집중)

> 목적: soft-engage 토크캡 수정을 실차에 넣기 전, **지금까지 모든 로그**로 근본원인과 수정 논리에
> 구멍이 없는지 스트레스 테스트. 결론: 근본원인 高확신, 수정은 저위험이나 인과 1개는 테스트로만 확정.

| C t=16.1 | 3.8 | +72 | **−155(돌림)** | +24 | 잡음 | 1 | **운전자개입** engage |

### 표에서 바로 나오는 사실
1. **손뗌 상태에서 고토크(≳100) engage는 한 번도 없음** (B t=5/6/7, C t=0~14 — 데이터 多).
2. **손뗌 engage는 딱 1회, 그것도 outTq=39(저토크)** (B t=15).
3. **운전자가 돌리면**(drvTq 큼) 중간토크에서도 engage (C t=5,16) — "핸들 흔들면 됨"의 경로.
4. **한번 engage되면 고토크(−264)도 유지** (C t=6~7) — engage 임계 ≫ 유지 임계(히스테리시스) 확정.

→ **근본원인 = "손뗌일 때 OP 토크가 크면 MDPS가 LKAS를 시작 안 함"** : 확신 높음(반례 없음, 통제된 비교 있음).

## 2. 핵심 통제 비교 (이게 각도·운전자 요인을 배제)

- **B t=6.1**: ang=**−0(완전중앙)**, drvTq=**+18(거의없음)**, outTq=**+409** → **미engage**
- **B t=15.1**: ang=**−13**, drvTq=**+1**, outTq=**+39** → **engage**

t=6.1이 t=15보다 **더 중앙**이고 운전자토크도 비슷하게 낮은데 **안 물림**. **유일하게 다른 변수 = outTq(409 vs 39).** → 물림/미물림을 가르는 건 **토크 크기**. (각도·운전자 원인 배제됨)

---

## 3. 새 통찰 — 왜 outTq가 자꾸 409로 포화되나 (악순환)

로그에서 **중앙(ang≈0)인데도 outTq=409**가 흔함(B t=6.1 등). 정상이라면 중앙에선 토크가 작아야 함. 원인은 **피드백 악순환**:

1. MDPS 미engage → 차가 안 돌아감.
2. 하지만 openpilot은 폴트를 못 봄(`steerFaultTemporary=0`) → "내가 조향 중"이라 믿고 **횡오차 적분/보정 계속** → 출력이 **포화(±409)**.
3. 포화된 고토크 → MDPS가 더 안 물림 → 1번으로.

→ **"토크가 자연히 낮아져 물리는 순간"이 드물게만 옴** (B t=15는 조건이 우연히 맞은 것). **그래서 사용자가 재현이 그렇게 힘들었던 것.** 즉 "손뗌+저토크"를 자연히 기다리는 건 비현실적 → **인위적 캡이 오히려 정답인 이유.**

## 4. 수정(soft-engage 캡) 스트레스 테스트 — 나빠질 시나리오 점검

| 우려 | 판정 |
|---|---|
| 미engage 중 캡 → 조향 약해짐? | **영향 0.** ToiActive=0이면 MDPS가 어차피 토크 0 적용. 우리가 뭘 보내든 차는 안 돎. 캡은 "물릴 기회"만 줌. |
| 캡50인데 MDPS가 "캡된 50"과 "자연 50"을 구분해 거부? | MDPS는 LKAS11의 `CR_Lkas_StrToqReq` **값만** 봄(내부 의도 모름). 50 보이면 50. → 물릴 것. (인과 leap, 아래 §5) |
| engage 후 램프업이 차를 튐? | 램프 ~3.6/frame ≈ 기존 DELTA_UP(3)라 **평소 토크증가와 동급**. + 히스테리시스로 고토크 유지 OK(C t=6~7). 튐 위험 낮음. |
| 운전자개입 engage(현재 되는 경로)를 캡이 막나? | 그 경로는 **운전자토크**가 트리거. OP토크를 낮추면(캡) MDPS는 더 관대 → **막지 않고 오히려 도움**. |
| ToiActive가 순간 0로 오독→ 주행중 캡? | ToiActive=0이면 어차피 토크 0적용이라 무해. 재램프 1s 미세 dip 정도. 로그상 ToiActive는 안정적. |
| 요청비트/ToiFlt 건드림(지난 역효과)? | **안 건드림.** 오직 토크 크기 clip. 폴트 연쇄 **구조적으로 불가.** |
| 적분 wind-up 악화? | 미engage 중 오차는 캡과 무관하게 쌓임(동일). engage되면 차가 돌며 오차 해소 → 적분 풀림. **캡이 악순환을 끊음.** |

→ **나빠질 구조적 경로 없음.** 최악=효과 없음(현상유지). 원복도 한 줄.

## 5. 정직한 확신도 (테스트 전)

| 항목 | 확신 | 근거 |
|---|---|---|
| 근본원인(손뗌+고토크→미engage) | **~85%** | 통제된 반례(§2) + 반례 없음 + 히스테리시스 확인 |
| 수정이 실제로 engage 유도 | **~75%** | "MDPS는 값만 본다"는 합리적 leap. 단 **손뗌+저토크 양성이 1개(B t=15)** 뿐 → 인과는 테스트로만 확정 |
| 수정이 안전(무해) | **~95%** | §4, 미engage중 무영향 + 비트 안건드림 + 원복 용이 |

**남은 유일한 불확실**: "인위적 저토크 캡이 (자연 저토크와 동일하게) engage를 유도하는가." 이건 로그로 더 못 좁힘 — **평소주행 1회면 `[ENGAGE 0->1] <손뗌>`으로 즉시 판명.**

---

## 6. 테스트에서 볼 것 (판정 기준)
- **`[ENGAGE 0->1] ... <손뗌(hands-off)>`가 자주 뜸** → 수정 성공(인과 확정). 캡값만 미세조정.
- 손뗌 engage가 여전히 안 뜨고 `<운전자개입>`뿐 → 캡값↓(40/35) 재시도. 그래도 안 되면 "MDPS가 engage에 운전자토크를 요구"하는 설계 → 캡만으론 부족, 다른 접근(단, 안전하게).
- 이상거동(튐/폴트) → 즉시 원복(`git reset --hard d3bca28`).

## 7. 결론
근본원인은 데이터로 탄탄하고, 수정은 **저위험·이유있음**. 유일한 인과 불확실성은 **무해한 실차 1회**로 확정된다. 지난 역효과(요청비트 토글)와 **작동방식이 근본적으로 다름**(토크만 캡, 비트/폴트 무접촉).
