# Soul EV (KIA_EV_SK3) 조향 engage — 심층 재분석 v3 (전체 로그 전수 재조립)

> 원칙: 결론을 정해놓지 않고, 지금까지 **모든 로그의 latch(ToiActive 0→1) 이벤트 8건**을
> 전수 조립해 후보 가설에 하나씩 대조. 이전 분석(v1/v2)의 오류·모순도 명시적으로 해소.

## 0. 구조적으로 재확정된 사실 (코드/safety 레벨)

| 항목 | 근거 |
|---|---|
| openpilot LKAS11은 bus0으로 100Hz 정상 송신 (ActToi=1, 토크, Flt=0) | sendcan 디코드 실측 |
| 순정 카메라 LKAS11(bus2)은 panda가 bus0으로 **차단** (fwd_hook, addr 832) | `safety_hyundai.h:321-322` |
| → MDPS는 openpilot의 LKAS11만 본다. 이중송신/충돌 **구조적으로 불가** | 확정 |
| >85° 시 요청비트 2프레임 컷+재상승(엣지)이 upstream 표준 동작으로 이미 존재 | `common_fault_avoidance`, MAX_ANGLE=85 |
| carrot 상시조향: latActive가 **v≈0.3~0.5에서** 걸림 → ActToi가 거의 항상 극저속에서 상승 | 전 로그 공통 |

**중요한 함의**: 순정 LFA는 정차에서 조향요청을 올리는 일이 없다. carrot은 올린다.
→ 이 차 MDPS는 "정차 중에 이미 요청이 켜져 있는" 상황을 설계상 본 적이 없는 입력을 받고 있다.

## 2. 가설 대조 결과

### H-토크크기 (v1의 주가설) — **반증 확정**
- cap30: 55km/h 손뗌에서 토크30으로도 미latch. #1(39에서 latch)은 토크가 아니라 다른 요인. 폐기.

### H-모드필드(LFA 모드 꺼짐이 게이트) — **정적 게이트로는 논리 반증** (사용자 지적)
- 모드필드는 순정값 pass-through로 **정적**. 정적 게이트면 "나중엔 잘 됨"이 불가능.
- 남은 형태: 순정 카메라가 **동적으로** 모드를 켜는 경우만 유효 → 내일 hb의 `cam Actm/LdwO` 변화로 판별.
- 참고: latch가 Sys=3(크루즈ON)과 Sys=4(조향만)에서 모두 발생 → **sys_state는 게이트 아님** 확정.

### H-운전자arm — **8건 중 5건 직접 부합, 사실상 확정된 '한 경로'**
- 정제된 형태: **지속적 운전자 토크(steeringPressed급, 대략 |col|≳150 수 프레임)가 있으면 MDPS가 arm되고,
  col이 낮아질 때(또는 개입 중) latch가 성립.**
- "살짝 건드리면 안 됨"(스파이크 arm 불가, cap30 t=14 반례로 입증)과 "흔들면 됨"(지속 입력) 모두 설명.
- "그냥 주행하다 보면 잡힘" = 주행 중 무의식적 개입/노면 토크가 어쩌다 임계를 넘는 순간.

### H-엣지 (ActToi 상승엣지를 '유효조건에서' 받아야 latch) — **미검증, 유일하게 남은 소프트웨어 해결 경로**
- 논리: carrot 상시조향은 ActToi를 **거의 항상 v≈0.3~0.5(무효조건)에서** 올림. 순정은 절대 그러지 않음.
  MDPS가 "요청 상승 시점의 조건"을 검사한다면, 정차에서 올라온 요청은 영원히 무시된다 — 관측과 일치.
- 지지 후보: #5 (v=15.4에서 로그 시작과 동시에 latch — 주행 중 engage였다면 엣지 즉발 latch).
  단 컨텍스트 불명이라 **증거로 못 씀**.
- 반례 없음(주행속도에서 손뗌 상승엣지를 만든 적이 한 번도 없어서 — **시험된 적 자체가 없음**).

### 미해명 잔여
- #1 (B t=15.1): 손뗌·저토크·중속 latch. 운전자 arm 잔여(t=7 +83은 임계 미달) 여부 불명. **내일 WAKE가 이런 케이스를 잡는 게 최우선 목적.**
- #4: 정차 blip. 물리적 의미 없음(직후 lat off).

## 3. 왜 형제차(코나/니로EV)는 안 그런가 — 현재 최선의 설명

코나/니로EV MDPS는 ActToi=1이면 조건 안 따지고 무는 구세대 수용 로직.
쏘울EV(SK3)는 LFA 세대 MDPS(CRC8 메시지 세대)로 **시작(arm) 조건 검사가 있는** 수용 로직.
CRC8 자체는 원인이 아니고(싼타페 반례), **carrot 상시조향의 "정차에서 요청 올림"과
이 MDPS의 arm 검사(운전자토크 또는 [미검증]유효조건 엣지)의 조합**이 이 차에서만 문제를 만든다.
→ 같은 carrot을 쓰는 코나/니로는 arm 검사가 없으니 무증상. 순정 쏘울EV도 무증상(순정은 정차에서 요청 안 올림).

## 4. 해결점 — 있다. 단, 어느 가설이 맞느냐에 따라 갈린다

### 판별 실험 (코드 무변경, 내일 주행에서 가능)
1. **[실험 E1 — 결정적]** 40~60km/h 주행 중, ToiActive=0(안 물린) 상태에서 **핸들 안 건드리고**
   조향만 껐다가 다시 켠다(인게이지 토글). → **유효속도에서의 손뗌 상승엣지**가 최초로 생성됨.
   - 즉시 latch되면(#5 패턴 재현) → **H-edge 확정** → Fix-B로 근본 해결 가능.
   - 안 물리면 → H-edge 기각 → H-운전자arm 단독 → 소프트웨어 근본해결 불가, 완화책으로 전환.
2. **[WAKE 수집]** 평소 주행에서 latch 순간 자동분석(`추정트리거:` 운전자토크/엣지/??) 다수 확보.
   특히 `??`가 나오면 제3의 경로가 있다는 뜻 → 재분석.
3. hb의 `cam[Actm/LdwO]`가 주행 중 변하는지 → 동적 모드필드 가설 최종 판정.

### Fix-B 설계 (H-edge 확정 시 적용, 사전 설계만 해둠 — 미구현)
> **"요청비트를 유효조건에서 올린다"** — 순정 LFA의 타이밍을 모사.
- latActive라도 **ToiActive=0이고 v < ~3m/s**인 동안은 `apply_steer_req=0` **그리고 `torque_fault=0` 강제**
  (기존 공식 `torque_fault = latActive and not apply_steer_req`를 이 구간만 오버라이드 —
  ToiFlt=1 연속송신은 과거 역효과의 원인이므로 **절대 금지**).
- v ≥ 3m/s가 되면 요청비트를 올림 → **유효조건 상승엣지**. 이후 ToiActive=1이면 통상 로직(유지).
- 정차로 ToiActive가 떨어지면 리셋 → 재출발 때 다시 유효엣지. (첫 인게이지/정차 후 재출발 모두 해결)
- 안전성: ToiActive=0 구간은 MDPS가 어차피 토크 미적용이라 **물리적 변화 0**. ActToi=0+ToiFlt=0은
  "lat 꺼짐"과 동일한 무해 상태. 폴트비트 무접촉.
- (보조) 그래도 안 물리면 3초 간격 2프레임 재엣지 — upstream >85° 메커니즘과 동일 캐덴스. 2차 검토.

### H-운전자arm 단독일 경우의 완화책
- "인게이지인데 미조향" 0.5s 지속 시 **명시적 경고**(방심 제거) + 사용 요령(지그시 잡았다 놓기 — 살짝 X).

## 6. (추가) E1/엣지-리프레시 실차 결과 — H-edge 반증, 최종 판정 (2026-07-02)

결정적 로그 (107km/h 주행 중 인게이지):
| t | 사건 | MDPS |
|---|---|---|
| 5.0 | **주행속도(29.6m/s)에서 인게이지 = 유효조건 상승엣지** | **거부 (4초+)** |
| ~7.7 | 엣지-리프레시 자동 컷/재상승 (WAKE 윈도우 `엣지=1`로 확인) | **거부** |
| 8.0 | 운전자 지그시 잡음 (col +302, prs=1) | 거부 |
| **9.3** | **놓는 순간 (col +5)** | **latch** |

- **H-edge 기각**: 유효속도 상승엣지 2회(인게이지 + 자동리프레시) 모두 무효.
- **H-운전자arm 최종 확정**: 이제 latch 9건 전부가 단일 메커니즘으로 설명됨 —
  **"지속적 운전자 토크(steeringPressed급, |col|≳150~300) 후 놓는 순간 latch"**.
  이전 미해명 건(#1 B t=15.1, #5)도 같은 패턴(직전 NUDGE/수동주행)으로 소급 설명됨.
- 모드필드 가설도 실측 기각: opTX가 이미 LFA-on 값(Actm=3, LdwO=2, FcwO=2)을 송신 중이었음
  (SEND_LFA가 런타임에 켜져 있었음 — 0x485 존재).
- 엣지-리프레시 실험 코드는 **제거**(음성 결과). 이 문서의 실험 이력이 재시도 방지 기록.

### 최종 결론
이 차(KIA_EV_SK3)의 MDPS는 **운전자 토크 arm 없이는 LKAS 오버레이를 시작하지 않는다.**
운전자 컬럼토크는 물리 센서라 소프트웨어로 위조 불가 → **자동 재장착은 구현 불가능.**
남은 개선 = 미장착 상태를 운전자에게 알리는 경고(방심 제거) + 사용 요령
("지그시 잡았다 놓기" — 스치는 터치는 임계 미달로 무효).

## 7. (정정) 사용자 실주행 반증 — 인과 역전, 최종 모델 v2 (2026-07-03)

노크(엣지-리프레시) 탑재 빌드 실주행에서 사용자 관측:
**"핸들을 안 잡아도 알아서 조향을 시작한다. 로그의 운전자 토크는 미조향으로 차가
옆차선으로 가서 내가 교정한 것(=결과)이지 시작 조건(=원인)이 아니었다."**

→ §6의 "운전자 arm 필수" 결론은 **역인과 오독**이었다. 정정된 모델:

**latch = "컬럼토크가 조용한 상태에서 신선한 요청(상승엣지, 저토크 시작)이 도달할 때".
운전자 토크는 시작을 돕는 게 아니라 오히려 latch를 지연시킨다(운전자 우선 양보).**

이 모델이 전 데이터를 재설명:
- 손뗌 latch가 전부 저토크 순간(39/13/2)이었던 것 = 엣지 직후 토크가 0부터 램프되는 순간.
- "놓는 순간 잡힌다"로 보였던 것 = 손 토크가 있는 동안 blocked → 놓아야 다음 노크가 먹힘.
- 노크 이전 시절 첫 인게이지가 영영 안 잡혔던 것 = 정차(v≈0.4)에서 올라간 요청이 stale,
  이후 엣지가 없었음. 노크가 3초마다 "신선한 요청+0부터 램프"를 재공급하며 해결됨.
- 107km/h 엣지 미latch = 그 순간 운전자가 핸들 접촉 중(col 29~174)이라 blocked.
- 노크 간격 1s→3s 무차이 = 지연의 지배 변수가 노크 주기가 아니라 "손이 조용해지는 시점".

**따라서 노크(엣지-리프레시)는 보조가 아니라 hands-off 시작을 가능케 하는 핵심 — 영구 유지.**
잔여 불확실: B t=15.1(엣지 없이 latch) 1건은 여전히 미해명(전체 11건 중 1건).

(후속: 노크는 실주행에서 "일시 양보→완전 풀림" 부작용이 확인되어 **제거**됨. §8 참조.)

## 8. (최종) 통합 모델 v3 — "요청 토크 ≈ 0"이 유일한 수용 조건 (2026-07-02 저속 토글 세션)

메인버튼 연동으로 재인게이지를 반복한 저속 세션에서 WAKE 7건 전수:

| WAKE | v(km/h) | 손 | **latch 순간 opTQ** |
|---|---|---|---|
| t=14.0 | 9 | 개입후 | **+4** |
| t=28.8 | 25 | **손뗌** | **+2** |
| t=39.7 | 19 | 개입 | **0** |
| t=53.0 | 15 | 개입중 | **−6** |
| t=63.7 | 16 | **손뗌** | **−2** |
| t=84.1 | 14 | 개입후 | **+9** |
| t=121.4 | 16 | **손뗌** | **+1** |

**7/7 전부 |opTQ| ≤ 9에서 latch. 거부 구간은 전부 토크 30~409.** 28초 거부(t=93~121)도
토크가 0을 지나는 순간(+1) 종료. 재인게이지 직후 미latch(거의 100%)도 토크가 큰 상태라 설명됨.

### 전 미스터리의 통합 해소
- "운전자 arm"(§6) = 착시. 운전자 개입 → driver torque limits가 **OP 토크를 0으로** 낮춤 → 수용.
- "속도 문턱" = 없음(16km/h 손뗌 latch 3건). 저속에서 안 잡히던 건 토크 windup 때문.
- 초기 soft-engage 캡 50/30 실패 = **문턱(≤~10)보다 캡이 높았음**. 캡이 토크를 상수로 고정해
  0 근처를 오히려 못 가게 함. 방향은 맞았고 값이 틀렸던 것.
- 노크의 가짜 효능 = 컷마다 토크가 0에서 재시작한 부수효과.
- B t=15.1 미해명 건 = outTq 39는 1Hz 샘플, 실제 latch 순간은 0 부근이었을 것.

### 최종 수정 (carcontroller)
**ToiActive=0(미적용) 동안 요청비트는 유지하되 토크를 0으로 송신** (10프레임 디바운스).
미적용 중 토크는 어차피 무시되므로 손실 0, latch 후 0부터 자연 램프업(soft engage 겸).
요청비트/ToiFlt 무접촉(과거 두 차례 역효과 방식과 무관).
